# Qiskit 2.0.3 → 2.4.2 移行記録

Qiskit を 2.0.3 から上げた作業の引き継ぎメモです。目標は 2.5.2 でしたが、上流のバグにより 2.4.2 が到達可能な上限でした。

手順そのものより、**踏んだ罠と、その検出に何が必要だったか**が引き継ぐ価値のある部分です。

| | |
|---|---|
| 到達バージョン | qiskit 2.4.2（目標は 2.5.2） |
| PR | #9 — base は `migration-qiskit-v2`（PR #8 に積む） |
| ブランチ | `upgrade-qiskit-2.4` |
| コミット | 8 件 |
| 実行 | local 15/15 pass、CI（ubuntu）緑 |
| 冪等性 | 14/15 完全安定、1 件は原因不明として台帳記録 |
| 既定インストール | 116 パッケージ |

> **最初に読むべき一点**
>
> 「notebook が実行を通った」は完了条件になりません。この repo のサイトは `.ipynb` に保存された出力をレンダリングし、ビルドはカーネルを起動しないため、**実行の成功と公開内容の正しさは別の主張**です。今回の作業で最も高くついた誤りは、その2つを混同したことでした。

## 1. 作業の手順

順序に意味があります。飛ばすと後段の判定ができなくなる依存関係があるため、実際に踏んだ順に記します。

### 1-1. 依存が解決可能かを先に確認する

コードを1行も読まず、レジストリのメタデータだけで判定できます。目標バージョンに上限をかけている直接依存を洗い、上限をかけているものが EOL か改名されていないかを調べます。

ここが通らなければ以降の作業はすべて無駄になるため最初に置きます。

### 1-2. ピン方針を決める

この repo の qiskit 群は5つのパッケージが相互に制約し合います（`qiskit-ibm-transpiler` が `qiskit-serverless` を固定し、それが `qiskit-ibm-runtime` に上限をかける）。厳密ピンを手で解く方式は更新に耐えないため、下限を宣言して `uv.lock` に再現性を持たせる形へ変更しました。

### 1-3. 判定の道具を作る

比較の基準がないまま更新すると、差分が出ても「更新起因」か「元からそう」かを区別できません。3つ作りました。

- `scripts/api-surface-diff.py` — 何が変わったかをドキュメントに依存せず確定する
- `scripts/compare-notebook-outputs.py` — 出力の現新比較を判定可能にする
- `scripts/run-notebooks.py` の `--check-idempotent` と `--warnings-report`

### 1-4. 更新して、失敗を1件ずつ潰す

実行は最初のエラーで止まるため、失敗は直列に現れます。1件直して再実行を繰り返します。

### 1-5. 再現性を担保してから出力を再生成する

再生成は公開内容への書き込みです。決定的でない状態で再生成すると、差分に「更新起因」と「実行ごとの揺れ」が混在し、**差分そのものが解釈不能**になります。

### 1-6. 現新比較し、構造変化を1件ずつ承認する

数値のみの変化はレポート、構造変化は理由付きで台帳に記録するまで失敗扱いです。

## 2. 発生した問題と対応

### 依存関係

#### qiskit 2.5.2 に到達できなかった

**症状** — `from qiskit.visualization import *` が `AttributeError` で失敗（toffoli Lab が使用）。

**原因** — qiskit 2.5.0 が `qiskit.visualization.__all__` を追加した際、その中に属性として存在しない `draw` を含めています。2.5.0 / 2.5.1 / 2.5.2 すべて影響し、2.4.2 と 2.3.1 は `__all__` 自体が無いため無影響です。上流のバグです。

**対応** — `qiskit>=2.4,<2.5` と上限を設定。**上限には理由をコメントで書いています** — 理由が無いと将来誰かが善意で外して同じ穴に落ちます。上流が修正すれば外せます。

#### resolver が壊れた環境を生成した

**症状** — 依存解決は成功したが `ModuleNotFoundError: No module named 'qiskit.synthesis.linear.linear_matrix_utils'` で import できない。

**原因** — `qiskit-ibm-transpiler` 0.13.0 は `qiskit>=1.4.2` と**上限を宣言していない**のに、qiskit 2.5 が削除したモジュールを import しています。resolver はメタデータしか見ないため検知できません。

**教訓** — **宣言された制約は互換性ではありません。** 解決が通ったことは動作の保証にならないので、解決の後に必ず実行して確かめます。

#### 最新版が torch と CUDA を引き込む

**症状** — `qiskit-ibm-transpiler` を qiskit 2.x 対応版に上げると、`qiskit-gym` 経由で `torch`、`cuda-toolkit`、`gymnasium`、`ray`、`qiskit-serverless` が入り、**116 → 211 パッケージ**になります。

**判断** — 利用者は AI transpiler Lab 1本のみで、それは IBM Quantum アカウントを要する `hardware` 区分のため CI では一度も実行されません。全 PR の CI と全学習者に CUDA のダウンロードを課す対価が釣り合いません。

**対応** — `[dependency-groups] ai-transpiler` に分離。バージョンは lock で管理され、必要なときだけ `uv sync --group ai-transpiler`。

### 検証基盤

#### `--save-outputs` が一度も書き込めていなかった

**症状** — `nbformat.write` が `AttributeError: 'dict' object has no attribute 'output_type'` で例外。

**原因** — `coalesce_streams` が `dict(output, text=text)` で `NotebookNode` を素の `dict` に変換していました。PR #8 に含まれるバグです。

**影響** — **PR #8 の「2回生成してバイト一致」という検証結果は偽でした。** 書き込みが失敗していればファイルは変わらず、ハッシュは当然一致します。ログの `15/15 passed` は notebook の*実行*成功を示すもので、*保存*の成否とは別の主張であり、その2つを混同していました。修正後の初回測定は 11/15 でした。

#### 冪等性の1ラウンド判定では足りない

**症状** — 2ラウンド化した最初の実行で `error-correction` が 2/2 ラウンドで不一致。それ以前の単一ラウンド測定では**すべて「安定」**と出ていました。

**原因** — `transpile()` に `seed_transpiler` が無く、ルーティングが毎回別の乱数を引いていました。同種の未指定は計6箇所ありました。

**対応** — `--check-idempotent` を `--rounds`（既定2）に変更。1ラウンドでは間欠的な非決定性を原理的に検出できません。

### 再現性

#### 警告に kernel の PID とテンポラリパスが入る

**症状** — grover の出力が毎回変わる。差分は `.../T/ipykernel_96562/3663264877.py:19: DeprecationWarning: ...` の `96562` の部分。

**影響** — 非決定性であると同時に、`/var/folders/...` という**マシン固有パスの公開**でもありました。漏洩スキャンは `/Users` と `/home` しか見ておらず、これを見逃していました。

**対応** — 保存時に `<ipykernel>.py` へ正規化。漏洩パターンにも追加。

#### part2 の間欠的な非決定性（未解決）

**症状** — `2024-spring-lab1-qiskit10-ja-part2` が全15本のバッチ実行時のみ、ラウンドの半分から全部で不一致。単独では3回すべて一致します。

**否定した仮説**

- 並列浮動小数点の総和順序 — スレッド数 1 と 8 で完全一致
- ipykernel パス — 正規化後も再現
- 時間・経過情報の混入 — コードに該当なし
- ローカルモードでシードが無効 — 同一シードで3回一致、無指定では不一致

**対応** — `scripts/known-nondeterministic.txt` に**否定した仮説を明記して**記録。「調べなかった」と「調べたが分からなかった」を区別するためです。ゲートは通り、他の notebook が動けば失敗します。

#### API 差分の誤検出が大量に出た

**症状** — 初版は 2.0.3 → 2.4.2 で 586 行を出力し、ほぼ全部がノイズでした。

**原因** — `dir()` ベースの差分は次を拾います。

- サブモジュール名
- 同一シンボルの再エクスポート（`Target` が約30モジュールで重複）
- モジュールローカルの漏れ（`pi`、`theta`、`rules`）
- Rust 実装化で `(*args, **kwargs)` になった class
- デフォルト値の `repr` に含まれるメモリアドレス

**対応** — 正規の定義元でのみ報告、class と関数のみ対象、`(*args, **kwargs)` は introspect 不能扱い、アドレスを正規化。**586 行 → 59 行**になり、残った全項目が本物になりました。

### 教材の内容

#### 「等価なユニタリなら数値は動かない」は誤りだった

**前提** — 非推奨クラスを関数形に置換する前に、パラメータ数・**パラメータ順序**・ユニタリの一致を6パターンで検証しました。順序の一致は VQE Lab が `x0` 配列を位置で束縛するため必須です。

**実際** — 数値は動きました。`TwoLocal` と `n_local` は同じユニタリを**異なるゲート列**で作るため、トランスパイル結果が変わり、ノイズ付き `FakeSherbrooke` の結果も変わります。VQE の最終エネルギーは 30 反復で `-2.81` から `-2.41` になりました。

**判断** — 解説文は「エネルギーを最小化しました」という定性的記述のみで数値を引用していないため受け入れ、台帳に記録。**等価なユニタリは等価なトランスパイル結果を意味しません。**

#### `version_check` が同じ罠を2回踏んでいた

**症状** — transpilation Lab の冒頭で「バージョンが違う」と表示されていました。

**原因** — 2.0 移行時に `'1.0.2'` 決め打ちを `'2.0.'` 決め打ちに置き換えただけだったため、マイナー更新でまた誤表示になりました。

**対応** — メジャーバージョンで判定するよう変更。この repo は `qiskit<3` を前提としており、マイナー更新で教材が誤表示すべきではありません。

#### 数えるまで範囲が分からなかった

**「132回」対「2行」** — MCX 系の非推奨は grover で各132回出ますが、**ソース上は2行**です。実行回数と修正箇所数は別物でした。

**13種対3種** — 非推奨は13種類ありますが、通常実行で**保存出力に残るのは3種類だけ**でした。Python の重複抑制やライブラリ内部での発生により stderr に到達しないためです。対応を強制される範囲は5分の1程度に絞れました。

#### 副産物 — transpiler のデフォルト変更が教材を改善した

**変化** — qiskit 2.4 で `qs_decomposition` の `opt_a1` / `opt_a2` のデフォルトが `True` から `None` になり、ユニタリ合成が変わりました。optimization level 1/2/3 の回路の深さは `205/156/156` から `217/182/182` へ。

**意味** — 2.0.3 では level 2 と 3 が**同一結果**で、level 3 を説明する節の説得力が落ちていました。2.4.2 では level 3 が再び最良になり、教材として改善しています。

**備考** — このデフォルト変更は `api-surface-diff.py` が実行前に検出しており、予測と実測が一致しました。

## 4. 次に同じ作業をする人へ

手順の骨格そのものは、注意深く進めれば自然に導けます。導けないのは以下です。

- **依存解決の成功を動作の保証と読まない。** 上限を宣言していないパッケージが実際には壊れていることがあります。解決したら必ず実行してください。
- **「実行が通った」を完了条件にしない。** サイトは保存出力をレンダリングします。実行の成功と公開内容の正しさは別の主張です。
- **バイト比較は複数ラウンドで。** 1回のパス対では間欠的な非決定性を取り逃がします。実際に、すべての単一ラウンド測定で「安定」と出ていた notebook が2ラウンド化した初回で検出されました。
- **出力の再生成は、自分のマシンをリポジトリに持ち込む行為です。** 絶対パス、認証状態、実行日時、メモリアドレス、kernel のテンポラリパス。すべて実際に混入した実績があります。
- **シードは `seed_transpiler` を忘れます。** ルーティングとレイアウトは乱数的に見えないため見落とします。
- **範囲は数えてから決める。** 警告の出現回数と修正箇所数は別、非推奨の種類数と対応が強制される数も別でした。

### ツールの使い方

すべて `scripts/` にあり、`CLAUDE.md` に一覧があります。順序は以下です。

```bash
# 1. 更新前に変更点を確定（真の削除・引数の消失・デフォルト変更・解決不能な __all__）
uv run python scripts/api-surface-diff.py qiskit --old 2.0.3

# 2. 実行して失敗を潰す
uv run python scripts/run-notebooks.py --group local

# 3. 冪等性が全緑になるまでシードを追加
uv run python scripts/run-notebooks.py --group local --check-idempotent

# 4. 出力を再生成
uv run python scripts/run-notebooks.py --group local --save-outputs

# 5. 現新比較（構造変化と環境混入で非ゼロ終了）
uv run python scripts/compare-notebook-outputs.py --base <更新前のref>

# 次のメジャーに向けた残債の棚卸し
uv run python scripts/run-notebooks.py --group local --warnings-report
```

判断が要る箇所は2つの台帳に理由付きで記録します。どちらも**理由の記載が必須**で、無いエントリは解析時に拒否されます。

- `scripts/accepted-output-changes.txt` — 読んで受け入れた構造変化。出力の digest に紐付くので、同じセルが再び変われば再確認を求めます
- `scripts/known-nondeterministic.txt` — 原因を探したが分からなかった非決定性。何を否定したかを書きます
